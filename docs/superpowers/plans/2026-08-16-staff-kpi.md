# Staff KPI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let staff see their own delivery/production KPI (and the owner see everyone's) over a selectable date range, computed from existing order data plus a new bakery-production log.

**Architecture:** One new DB table (`production_logs`) for bakery production not tied to a customer order, a small entry-point modal on the existing KDS screen to log it, a pure computation module (`src/lib/kpi.js`) that turns raw orders/production-logs into per-staff numbers, and a new `KpiScreen.jsx` that renders those numbers — self-only for regular staff, everyone for owner/admin.

**Tech Stack:** React 18 (plain JSX, inline `style={{...}}` objects using `var(--...)` design tokens), Supabase (Postgres + RLS), Vite. **No test runner is configured in this project** — verification for every task is manual: run `npm run dev`, open the relevant screen in the browser, and exercise the feature; `npm run build` confirms it compiles.

## Global Constraints

- KPI is a viewing tool only — no automatic salary calculation, no ranking/comparison UI (per the design spec).
- Kitchen KPI shows 3 separate numbers per staff: order count, product-qty-from-orders, product-qty-produced — never combined into one total.
- A staff member working both bếp nóng and bếp lạnh gets one combined KPI — no per-station split.
- Staff-to-KPI matching is by exact string match of `profiles.full_name` against `orders.shipper_staff_name` / `orders.kitchen_staff_name` / `production_logs.staff_name` — accepted limitation, no dedup/disambiguation logic needed.
- Production log entries default to today's date and are not backdatable in this version (no date picker on the entry form).
- Kitchen-lead-sees-subordinates visibility is explicitly out of scope — do not build it.
- Migrations in this repo are hand-run by the project owner in the Supabase SQL Editor, never auto-applied — every new migration file must start with the comment `-- Run manually in Supabase SQL Editor. Safe to re-run (idempotent).` and use `if not exists` guards, matching every existing `supabase/migrate_*.sql` file.
- Do not reproduce the existing `usePermissions()` bug (`src/lib/usePermissions.js` spreads `PERMISSION_CHECKS` — functions of shape `(role) => boolean` — directly onto the returned object without binding `profile.role`, so e.g. `permissions.canViewAllReports` is a **function reference, always truthy**, not a boolean; any `if (!permissions.canViewX)` gate built that way is dead code). This plan's screen must gate visibility using `hasAnyRole(profile, [...])` from `src/lib/roles.js` instead — the same pattern already used correctly in `KdsScreen.jsx`.

```sql
create table if not exists production_logs (
  id uuid primary key default gen_random_uuid(),
  product_id uuid references products(id) on delete set null,
  product_name text not null,
  qty numeric not null check (qty > 0),
  staff_id uuid references profiles(id) on delete set null,
  staff_name text not null,
  work_date date not null default current_date,
  created_at timestamptz not null default now()
);

alter table production_logs enable row level security;

drop policy if exists "read production_logs" on production_logs;
create policy "read production_logs" on production_logs for select
  using (auth.role() = 'authenticated' and public.is_approved());

drop policy if exists "insert production_logs" on production_logs;
create policy "insert production_logs" on production_logs for insert
  with check (auth.role() = 'authenticated' and public.is_approved());
```

  - `fetchProductionLogs({ from, to } = {})` → `Promise<Array<{ id, product_id, product_name, qty, staff_id, staff_name, work_date, created_at }>>`. `from`/`to` are `'YYYY-MM-DD'` strings, both optional, filtering on `work_date`.

- [ ] **Step 1: Add both functions**

```js
export async function addProductionLog({ productId, productName, qty, staffId, staffName }) {
  const { error } = await supabase.from('production_logs').insert({
    product_id: productId || null, product_name: productName, qty,
    staff_id: staffId || null, staff_name: staffName,
  });
  if (error) throw error;
}

export async function fetchProductionLogs({ from, to } = {}) {
  let q = supabase.from('production_logs').select('*').order('work_date', { ascending: false });
  if (from) q = q.gte('work_date', from);
  if (to) q = q.lte('work_date', to);
  const { data, error } = await q;
  if (error) throw error;
  return data;
}
```

### Task 4: `src/lib/kpi.js` — pure KPI computation

**Files:**
- Create: `src/lib/kpi.js`

**Interfaces:**
- Consumes: `haversineKm` from `src/lib/geo.js`.
- Produces:
  - `computeShipperKpi(orders, staffFullName)` → `{ orderCount: number, totalKm: number }`.
  - `computeKitchenKpi(orders, productionLogs, staffFullName)` → `{ orderCount: number, productsFromOrders: number, productsProduced: number }`.

This is a plain function module with no React/UI — both `KpiScreen.jsx` (Task 5) and any future consumer call these against already-fetched `orders`/`productionLogs` arrays.

- [ ] **Step 1: Write the module**

```js
import { haversineKm } from './geo';

export function computeShipperKpi(orders, staffFullName) {
  const matched = orders.filter((o) => o.shipper_staff_name === staffFullName && o.status === 'hoan_thanh');
  const orderCount = matched.length;
  const totalKm = matched.reduce((sum, o) => {
    const km = haversineKm(o.pickup_lat, o.pickup_lng, o.delivery_lat, o.delivery_lng);
    return sum + (km || 0);
  }, 0);
  return { orderCount, totalKm: Math.round(totalKm * 10) / 10 };
}

export function computeKitchenKpi(orders, productionLogs, staffFullName) {
  const matched = orders.filter((o) => o.kitchen_staff_name === staffFullName);
  const orderCount = matched.length;
  const productsFromOrders = matched.reduce((sum, o) => {
    const items = o.order_items || [];
    return sum + items.reduce((s, it) => s + (Number(it.qty) || 0), 0);
  }, 0);
  const productsProduced = productionLogs
    .filter((p) => p.staff_name === staffFullName)
    .reduce((sum, p) => sum + (Number(p.qty) || 0), 0);
  return { orderCount, productsFromOrders, productsProduced };
}
```

```jsx
function rangeFor(preset, customFrom, customTo) {
  const todayStr = localDateStr();

  const days = RANGE_DAYS[preset] ?? 0;
```
